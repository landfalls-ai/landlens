# History

Every change, in order, with the decisions along the way.

| Date | Change | Notes |
|---|---|---|
| 2026-11-14 | The study: project skeleton; OpenLens (`f1a960f`, its last open-source commit), Freelens (`2547f55`), the ACP spec (`13b7658`), the ACP TypeScript SDK (`b93e77b`) and claude-agent-acp (`7e857d5`) pinned in `scripts/fetch-upstream.sh`; Craft Anything 0.6.1 fetched and verified; the released Freelens 2.0.0 studied statically (fuses, asar inventory, app graph) and source graphs built; a live ACP handshake with Claude Code; four research reports, `research.md`; `plan.md` proposed | The user asked for an OpenLens-like IDE whose headline is an ACP client that runs their own Claude Code against the cluster they are looking at. | 2026-11-14 | Wave 1, the shell: pnpm workspace; `landlens-kube-proxy` (Go, client-go) holds each cluster's credentials behind a per-process secret and mints the front door's loopback certificate; `@landlens/kube` (kubeconfig catalog, discovery, SelfSubjectAccessReview, paginated list + watch with bookmarks and 410 relist, a shared watch hub, the TLS front door with per-token policies and an audit trail, the tool kubeconfig with an env-only exec credential); `@landlens/contracts` (zod-validated IPC); the Electron app (sandboxed renderer, preload bridge, CSP, navigation and permission guards; catalog, sidebar from discovery, virtualized live tables, details with containers, conditions, events and YAML); fuses script; docs `architecture.md`, `security.md`, `development.md`, `limitations.md`, `roadmap.md` | Checked live on OrbStack: 24 pods across namespaces update live; an agent-style read-only token's `kubectl get pods` works while `kubectl delete pod` and `kubectl get secrets` are refused by Landlens before the cluster sees them; the IDE token reaches the API server; Secret values never reach the renderer. Changed from the plan: the front door is TLS + HTTP/1.1 (kubectl sends credentials only over TLS; the renderer uses IPC, so HTTP/2 isn't needed); kubeconfig parsing without `@kubernetes/client-node`. Craft Anything confirmed the hardened fuses on a cloned Electron.app. Tests: 34 kube, 10 desktop, 5 Go, 7 integration, 6 e2e |
| 2026-11-14 | Wave 1 security review fixes (Fable review of the wave-1 code): the sidecar secret moves from the environment to stdin; `Impersonate-*` headers are stripped by the sidecar and refused by the front door; the loopback certificate is a leaf; 502s are generic; IPC names must meet Kubernetes naming rules and kinds must be in discovery; `apiPath` validates instead of encoding; Secret lists and anything from `secrets` are redacted; `isAppUrl` is exact and dev overrides are ignored when packaged; the build carries the CSP as a `<meta>` tag; read tokens get an allowlist of non-resource paths; namespace limits use discovery scope and fail closed; `#`, spaces and control characters are refused in paths; upgrades are audited with the cluster's answer; the watch hub replays after returning the subscription id, caps subscriptions, replaces failed watchers and stops a cluster's watches when its sidecar exits; connects are deduplicated; the watcher's backoff is abortable and repeated 410s back off | Two high findings (secret readable with `ps eww`; unvalidated names could build paths such as a Secret list) and seven medium. The 410 test found a real spin: a server that lists fine but answers every watch with 410 made the watcher relist in a loop; counters now reset only after a watch runs its course. `page.evaluate` is exempt from CSP, so the e2e test injects an inline script and a string timer instead. Tests: 50 kube, 13 kube-mcp, 10 desktop, 6 Go, 7 integration, 8 e2e |
| 2026-11-14 | Wave 2, the agent: `@landlens/acp-host` starts `claude-agent-acp` 0.107.0 (ACP v1) with your Claude Code login; one session per dock with its own read-only front-door token, tool kubeconfig, MCP token and folder; `@landlens/kube-mcp` serves nine read-only cluster tools (`cluster_overview`, `describe`, `get_logs`, …) on a loopback MCP server, each call through the front door; the dock streams answers, thinking, tool cards, plan and permission asks; "Ask Claude" attaches an object; `deploy/scenarios/crashloop.yaml`. Then the fixes from a Fable security review of wave 2: the session loads none of your settings, hooks, plugins or MCP servers (they ran unsandboxed), has no web tools, gets an allowlisted environment, and its shell can read nothing in your home folder but its own; the front door scrubs every agent response (kubectl included) and refuses what it can't scrub; the SOCKS proxy goes to the front door too; tokens are revoked when Claude Code exits or the window reloads; main checks modes, model choices and answers; "Ask Claude" reads with the session's token; the cluster's version string is checked; links show their host; the tool kubeconfig is read-only. Found while checking the fixes: the wave 1 leaf certificate was refused by Electron's BoringSSL, so the MCP tools had never worked inside the app (the earlier e2e passed on kubectl alone); the front door's certificate is now a leaf signed by a one-run CA whose key is discarded. Tests: kube 70 + 7 on OrbStack, kube-mcp 8 + 4, acp-host 8 + 2 live with Claude Code, desktop 10 + 9 e2e (live agent), Go | Changed from the plan: no `~/.claude` settings, skills or plugins in agent sessions (chosen skills move to wave 3); `network.httpProxyPort` (and `socksProxyPort`) set to the front door is how the sandbox lets kubectl reach it; Landlens's MCP tools are pre-allowed; sessions are forced to Manual mode. Live: asked "Why is this pod crashlooping?", Claude Code (Opus 5.5) read the previous logs and the ConfigMap with the MCP tools and named the missing `DATABASE_URL` |
| 2026-11-14 | The Iris redesign ([design.md](design.md)), built from a designer's spec and mockup: tokens as CSS custom properties, dark and light; Geist, Geist Mono and lucide icons bundled; one sidebar with a cluster switcher that folds to a rail; width rules that keep the table near 600px with the drawer and dock open, the drawer floating at 1024×700; the Overview as the landing page (verdict, tiles, problems, warnings, nodes); quiet healthy rows, loud failing ones; the drawer's diagnosis card, linked owner and node, conditions checklist, numbered YAML; the dock's grouped tool calls, ask card and composer; a centred welcome; ⌘K Jump to; macOS inset title bar. Before it, `cluster:health`: `packages/kube/src/health.ts` computes nodes, pod counts, deployments, problems and recent warnings once, served over IPC to the Overview and shared by the agent's `cluster_overview` tool | The user found the old UI "looks really bad". Decisions: land on Overview (the one required e2e change clicks Pods after connecting); Logs and Metrics tabs shown disabled with a wave 4 note, where the spec said not to ship placeholders; the diagnosis's last line only from the container's termination message, no log fetch; the platform reaches the page as a `data-platform` attribute, no new bridge power. Tests: kube 73, kube-mcp 8, acp-host 8, desktop 10 + 10 e2e with the live agent (Overview, light and 1024×700 screenshots added) |
| 2026-11-14 | Graphs ([metrics.md](metrics.md)), pulled forward from wave 4 (metrics) and wave 6 (Clickland): `@landlens/metrics` picks the source per request: Clickland when a key is stored and it answers for the cluster's `k8s.cluster.name`, else metrics-server sampled every 15s into a one-hour ring buffer while a view asks, else none with the reasons; one channel, `metrics:series` (cluster, namespace, node, deployment, statefulset, daemonset, pod; 1h, 6h, 24h), plus the Clickland settings channels; the key in safeStorage, never sent to the renderer; Connect Clickland (status bar and empty states) with Test (health, filters, a query) and Save.
